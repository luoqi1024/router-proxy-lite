# 兼容性与验证范围

当前为开发预览。以下记录描述软件测试范围，不构成同型号所有设备或其他固件的兼容承诺。

## 设备范围

| 设备 | 固件 | 架构 / 系统 | 验证状态 |
| --- | --- | --- | --- |
| 小米 AX1800（RM1800） | 原厂 MiWiFi 1.0.394 | ARMv7 / IPQ6018 / Linux 4.4.60 | 单台设备首轮安装、联网与故障恢复通过 |
| 其他型号 / ARM64 / MIPS | 未验证 | 未验证 | 暂不提供完整安装包支持承诺 |

测试使用原厂固件，无需重新分区。安装依赖 root、BusyBox、procd、iptables、TUN、IPv4 转发、策略路由和 `br-lan`。原厂系统带有 OpenWrt 衍生组件，不等于支持任意标准 OpenWrt 插件。

## 已验证功能

- ARMv7 压缩程序可执行，OpenSSL 可用于缺少 `sha256sum` 的固件；同分区暂存与重命名安装通过。
- 管理页仅绑定 LAN，登录和真实运行模式正常。
- 单个 AnyTLS 节点的配置检查、HTTPS、TCP/UDP DNS 和 SOCKS5 UDP/STUN 往返通过。
- LAN 接管与 DNS 重定向规则计数增长。SOCKS UDP 测试不能替代全部客户端 UDP 应用验证。
- 开启、关闭、全局、直连、智能分流切换通过；低内存切换修复后经 API 与网页复测。
- 内核 SIGTERM 或自有防火墙入口丢失时，管理程序停止接管并清理；可重新开启。
- 服务重启恢复节点和策略。服务重启不等同整机重启或断电启动。

## 空间与内存

当前完整 ARMv7 开发包约 8.83 MiB，具体构建见 [资源与源码准备](PROVENANCE.md)。安装器要求完整文件空间之外至少 2 MiB 余量和 64 MiB 可用 RAM。`/tmp` 使用 RAM，不能当作独立闪存容量。

UPX 只减小磁盘文件；运行时内存需求随连接数和负载变化。尚未完成持续峰值、吞吐和长时间压力测量，因此不提供固定并发容量承诺。

已修复低内存设备上两个内核同时运行配置检查导致切换失败的问题：已有内核运行且可用 RAM 不足 64 MiB 或无法读取时，先停止旧内核，再检查和启动新配置；失败则尝试恢复。该门槛不是内存硬上限，切换可能短暂断流。
