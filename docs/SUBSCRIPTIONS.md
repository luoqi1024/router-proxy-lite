# 订阅管理

以下功能属于 `v0.1.0-alpha.2-dev` 源码，尚未包含在已发布的 Alpha 1 安装包中。

该开发构建已在 AX1800 原厂 MiWiFi 1.0.394 上完成保留配置升级、两套订阅切换和服务重启验证；测试范围见 [实机清单](HARDWARE-TEST.md)。这仍不是可由首次安装命令执行的自动升级。

## 添加和切换

在“节点 → 导入订阅”填写名称，再粘贴 HTTPS 链接或 Clash / Mihomo 配置内容。最多保存三套；有现有订阅时，新订阅先保存，不改变当前节点或重启代理。第一套导入后代理默认关闭。

在“当前订阅”菜单中选择要使用的一套，页面显示该订阅的节点。每套分别记住所选节点、故障自动切换开关和备用名单；上网策略以及代理总开关共用。代理已开启时，切换订阅会应用新节点，现有连接可能短暂中断。应用或保存失败时尝试恢复原配置，不自动删除旧订阅。

## 更新和删除

- 点击“更新”只更新当前订阅。同一链接再次导入也会更新对应的一套，不占新名额。
- 粘贴内容的配置没有可下载链接，更新按钮不可用；可删除后重新导入。
- 已有节点身份在更新后消失时，当前订阅的代理会关闭，需确认新节点再开启；备用名单中失效的节点会移除。
- 要删除一套，先在菜单中选择它、关闭代理，再点“删除”并确认。删除无法撤销。删除后选中一套剩余订阅，保持代理关闭。
- 达到三套上限后，新链接或粘贴内容会被拒绝，原有三套保留；已有链接仍可更新。

## 存储和旧配置

三套订阅共用一份代理内核、证书和规则，只保存解析后的节点，不保存原始订阅全文或重复的内核。配置 JSON 采用紧凑格式，总大小限制为 512 KiB；超限或写入失败会拒绝保存。每套仍最多 512 个节点，原始导入上限为 2 MiB。实际新增占用取决于节点数和字段长度。

旧版单订阅配置会在读取时作为第一套保留，密码、节点选择和备用名单不重置。成功保存后使用 schema 2；旧版程序无法读取该版本，因此维护升级前需保留旧配置备份。新增 HTTPS DNS 同时需要新版管理程序和新版精简内核，不能只替换其中一个。首次安装命令仍不支持覆盖升级。

## DNS 和订阅规则

开发版智能分流匹配的国内域名使用直连 DNS，其余 DNS 通过当前节点发送 HTTPS 查询，使用固定 IP 连接，验证 TLS 证书，不需要先解析 DNS 服务域名。全局代理的 DNS 同样走当前节点。这避免依赖代理出口开放 TCP 53 端口。

导入时读取节点信息，不导入订阅里的完整规则、策略组、扩展脚本或 DNS 设置。分流由 RouterLite 的上网策略控制。节点支持的传输能力仍取决于其服务端；HTTPS DNS 不会让不支持 UDP 的出口获得 UDP 能力。
