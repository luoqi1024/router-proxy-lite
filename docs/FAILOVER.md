# 备用节点自动切换

在“节点与订阅”页面操作：

1. 先选择平时使用的节点。
2. 勾选该节点及至少一个备用节点，共 2–5 个。
3. 打开“开启自动切换”，点击“保存名单”。

功能默认关闭，名单和开关保存在设备本地，重启管理服务后继续使用。代理关闭、全部直连或内核未运行时暂停检测；电脑演示模式只保存设置，不发起网络探测。

## 什么时候切换

每 30 秒检查当前节点，通过该节点请求 Google 的 generate_204 HTTPS 地址；失败时再尝试 Cloudflare 的 trace HTTPS 地址。每个请求最多 5 秒，任意一个返回成功即可。保持正常证书验证，超时、连接失败、证书错误等都可能导致本轮失败。

连续 3 轮失败后，依次检查保存名单中的其他节点，找到第一个可用节点后应用并保存。切换会重新建立代理连接，已有下载或通话可能短暂中断。一次备用检查或切换结束后，至少间隔 2 分钟才再次尝试备用名单；期间仍检查当前节点。

这不是即时切换或测速：发现故障通常需要约 1–2 分钟，尝试备选和应用配置还需要额外时间。两个探测网站同时不可达时，也可能将节点判为不可用；探测通过不能保证所有网站都能访问。

## 手动操作与异常情况

- 当前节点正常时不更换，不自动回到先前节点，不做负载均衡。
- 手动选择名单以外的节点会关闭自动切换。重新勾选名单并保存即可开启。
- 订阅更新后会移除失效的备用条目；少于两个有效节点或当前节点不在名单时，关闭自动切换并提示重新确认。
- 全部备用都失败时保留当前选择，显示异常并稍后重试，不擅自切换到全部直连。
- 切换应用或保存失败时尝试恢复原配置，可在“设备与记录”查看结果。

## 实现与资源

管理程序复用同一个代理内核。只把名单中的节点加入内核运行配置，备用节点按需逐个探测，不额外启动代理进程，也不引入数据库或完整测速模块。

探测入口仅监听本机回环地址，并强制绑定对应节点，不会因为智能分流走直连而误判节点可用。新增入口使用本机端口 17900–17905，普通 LAN 设备无法直接访问。

代码回归、真实内核配置检查和浏览器交互已完成；新增功能的实机内存峰值、断线恢复与长期稳定性尚待验证。原有单节点实机结果不等于自动切换已完成实机验收。
