# 从下载到开始使用

当前公开版本为 [v0.1.0-alpha.1](https://github.com/luoqi1024/router-proxy-lite/releases/tag/v0.1.0-alpha.1)，仅提供 ARMv7 安装包。小米 AX1800 / MiWiFi 1.0.394 已完成候选包离线新安装、文件校验和人工回退。手机首次设密的完整人工验收、新规则端到端联网、整机重启和长期稳定性仍未完成；此版本供愿意自行维护的用户试用。

## 用户流程

1. 自行解锁路由器 SSH，确认地址、root 账号和密码或密钥。路由器先按原厂方式正常联网。
2. 从可信发布渠道获得对应架构的安装入口或完整包，核对发布者提供的 SHA256。SSH 密码用于登录路由器，不填进我们的网站或上传到第三方。
3. 通过 SSH 在路由器执行安装入口。入口检查设备、旧代理、内存和存储，自动选择 `/data`，不足时检查 `/overlay`。
4. 安装完成后，SSH 终端显示管理网址；管理服务设为开机启动，代理尚未开启。
5. 手机/电脑连接这台路由器的主 Wi-Fi 或 LAN，在浏览器打开显示的网址，首次输入两遍新管理密码，设置成功后进入管理页面。
6. 导入 Clash/Mihomo 订阅或粘贴配置，选择节点、策略，然后开启代理。之后从网页操作，电脑无需一直开机。

SSH 凭据和网页管理口令是两套凭据。管理页绑定路由器的 LAN 地址，未向 WAN 或公网开放；SSH 连接使用的地址可能是 WAN 地址，两者不一定相同。

首次安装不生成密码，也没有通用默认密码。首次设置必须完成，才能查看配置或开启代理；关闭终端或重启程序不会跳过设置。密码要求 9–128 个字符。请在自己的可信 LAN 上及时完成首次设置，第一个完成设置的人会成为管理者。

登录后可在“设置 → 修改密码”修改，无需再次输入旧密码；保存后所有管理会话退出，代理继续运行。已有安装更新程序时保留原密码，不会重新开放首次设置。早期版本生成的随机密码仍然有效，无需重装。

## 在路由器终端直接安装

维护者发布的 `install-routerlite.sh` 内嵌该版本每个文件的大小和 SHA256，只通过 HTTPS 下载固定版本的文件，并逐个校验后安装。不跟随 `latest`，不下载远程脚本直接执行，不解压未知在线归档。

将可信入口文件放到路由器后：

```sh
sh install-routerlite.sh --check
sh install-routerlite.sh
```

`--check` 只检查环境和预计空间，不下载或启动服务。正常安装直接下载到所选分区的 `routerlite.stage`，最后同分区重命名，不同时保留压缩包和第二份程序。

下载失败时检查路由器系统时间、网络和 CA。固件缺少可信 CA 时，可以通过 `--cacert` 指定自己上传的可信证书包，或使用离线安装。不会使用 `curl -k` 或降级 HTTP；部分旧 curl 不支持所需 HTTPS 选项时也应使用离线入口。

公开安装入口，无需 GitHub 账号或令牌：

```sh
curl -fL --proto '=https' --proto-redir '=https' https://github.com/luoqi1024/router-proxy-lite/releases/download/v0.1.0-alpha.1/install-routerlite.sh -o /tmp/install-routerlite.sh && sh /tmp/install-routerlite.sh
```

命令下载成功后才执行。入口通过 GitHub HTTPS 分发，内嵌的哈希用于检查后续文件的完整性，不能防御发布账户本身被入侵。完整离线包及所有下载资产的 SHA256 在同一 Release 中提供。

## 离线完整包

离线包名为 `routerlite-0.1.0-alpha.1-armv7.tar.gz`，附 `DOWNLOAD-SHA256SUMS`。在电脑核对来源和哈希后，可在电脑解压，再通过 SCP/SFTP（固件缺少 SFTP 时使用 SCP 的兼容模式或其他 SSH 文件工具）上传完整目录，避免路由器同时存放压缩包和解压副本。

在已上传的完整包目录内执行：

```sh
sh scripts/setup.sh --check
sh scripts/setup.sh
```

通常自动选择安装位置。需要避开双份闪存占用时，可先核实空间，把完整包直接上传到 `/overlay/routerlite.stage` 或 `/data/routerlite.stage`；入口识别这种布局，仅要求上传后仍剩 2 MiB，并安装到同级 `routerlite`。不要盲目把完整包放 `/tmp`，因为它占用 RAM。

高级用户可指定 `--root /overlay/routerlite`，不会把任意路径当作安装目标。直接调用底层 `scripts/install.sh --experimental` 的默认行为仍是不设开机启动；交互较少的 `setup.sh` 则在服务健康检查通过后启用自启动。

## 检查失败时

| 提示 | 处理 |
| --- | --- |
| 架构不支持 / 缺少 procd、TUN、br-lan、IPv4 转发 | 当前固件未适配，停止安装，不自动刷机或改系统配置 |
| 旧代理运行、规则或自启动存在 | 先备份并用旧程序自己的方式停止、关闭其自启动，再安装 |
| 内存不足 | 安装至少需要 64 MiB 可用 RAM；停止旧代理后重新检查 |
| 没有合适分区 | 需要完整文件空间加至少 2 MiB 余量，不扩分区、不删除原厂文件 |
| 已有安装或暂存目录 | 保留内容供核实，拒绝覆盖；这不是升级器 |
| 下载/哈希失败 | 不执行新程序，清理本次下载清单中的暂存文件；未识别文件保留 |
| 管理页启动失败 | 尝试停止新服务、移除新启动链接，保留安装目录和私有状态供诊断 |

异常断电或 SIGKILL 可能留下暂存目录或安装锁；入口会拒绝覆盖，需维护者先检查。不承诺所有中断都自动恢复。程序服务重启测试已通过，但整机重启与断电启动仍需实测。

## 维护者生成安装产物

先构建并校验完整 bundle，再生成仅离线产物：

```powershell
./tools/bundle.ps1 -BundleName routerlite-armv7-install-preview
python tools/package-install.py --bundle dist/routerlite-armv7-install-preview --output dist/install-preview --version 0.1-install-preview
```

发布渠道确定后，向生成器额外传入 `--base-url`（实际的、带版本的 HTTPS 资产目录），输出会增加 `install-routerlite.sh` 和扁平文件资产，例如 `bin--routerlite`。GitHub Release 可以将这些文件作为同一版本的附件。生成器不上传任何内容，不修改仓库可见性。

生成器拒绝缺文件、校验失败、重复/不受支持路径、符号链接和未列入清单的文件，防止把开发目录里的私人状态一起打包。入口脚本本身是信任起点，内嵌哈希不是对发布者身份的独立签名；正式发布还需完成 [发布清单](RELEASE.md) 的资源来源、许可和硬件验收。

2026-09-29 本地验收：11 项安装/打包隔离测试、3 项文件校验测试、4 项网络事务模拟测试通过；10 个 shell 文件语法检查通过。完整包 9,230,383 bytes（约 8.80 MiB），在线入口预估安装前需 11,172 KiB 空间，含文件块取整及余量。网络下载通过模拟 curl 测试了参数、成功与失败路径，尚未从正式 HTTPS 发布渠道到实机做端到端安装。
