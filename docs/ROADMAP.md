# 全屋代理的后续重点

基于 2026-09-29 的源码与现有测试记录。以下为待办建议，不代表已实现或通过实机验证；验收项目以 [硬件清单](HARDWARE-TEST.md) 为准。

## 优先顺序

| 优先级 | 项目 | 当前情况与完成标准 |
| --- | --- | --- |
| 1 | 异常恢复与清楚的状态 | 已有服务自启动、备用节点切换、内核退出后的规则清理。内核异常退出或自有规则丢失时，目前停止接管，需要手动重试。补充有次数限制、退避的恢复和一键重试；区分“进程运行”和“节点可用”。全部节点失败时不擅自改为直连。 |
| 1 | 断电与多设备稳定性 | 完成整机重启、断电启动、上联网口重连、DHCP 变化、管理进程强杀、持续负载测试。测量 RAM 峰值、CPU、吞吐及闪存写入；文件体积不能代替内存测量，Go 的内存限制也是软目标。 |
| 1 | 流量覆盖检查 | 当前只接管 IPv4，LAN 有全局或 ULA IPv6 时拒绝启用；运行期间检测到 IPv6 会停止接管。验证客户端 DNS、DoH/DoT、UDP 和硬件加速是否绕过，明确问题后再设计 IPv6 支持。 |
| 2 | 订阅自动更新 | 当前只有手动更新。增加可关闭的定时刷新；失败保留旧订阅，节点失效给出提示，避免无变化也重启内核。订阅链接无法直连时提供明确诊断和可选的代理下载路径。 |
| 2 | 维护与恢复 | 增加配置导出/恢复、脱敏诊断、可回退的手动升级。导出文件含订阅凭据，需明确提示并避免混入诊断；低空间或写入失败时必须保留可用版本。自动升级排在回退验证之后。 |
| 3 | 少量例外规则 | 确有需要时增加“这个域名直连/代理”或“这台设备直连”，避免把整个规则编辑器搬到页面。先验证稳定设备识别及 DNS 对规则的影响。 |

日常页面保持三个入口：概览显示状态、节点和策略；节点页导入、更新和选择备用名单；设置页提供密码、检查与记录。运行参数和发行验证进度留在文档，不塞进日常操作页。

## 体积与运行开销

当前 ARMv7 安装目录约 8.84 MiB：代理内核约 6.35 MiB、管理程序约 2.14 MiB，其余约 0.35 MiB 为规则、证书、脚本与许可。

- 已使用裁剪的协议注册、去调试信息、UPX、单内核进程；网页使用原生 HTML/CSS/JS，无前端运行框架或路由器端数据库。
- 本轮清理口号、装饰元素和对应样式，让页面更短；这只能减少几 KiB，不能明显降低代理转发负载。
- 暂不重写管理服务或继续删除协议。进一步裁剪内核需要先测量收益，再核对真实订阅的协议和传输兼容性；证书、国内规则和许可文件保留。
- 性能优化先针对实测问题：减少无变化的配置写入/内核重启，控制并发探测和订阅解析峰值，避免记录每次网络访问或频繁写闪存。
- 不加入全节点带宽测速、复杂图表、插件市场、多内核切换。需要时优先提供按需的连通性检查。

## 本轮完成

- 去掉英文口号、欢迎语、装饰路由图、重复帮助和固定显示“已连接”的标识。
- 导航简化为“概览 / 节点 / 设置”；切换规则折叠，保留策略区别、范围、密码要求和连接中断提示。
- 退出登录放到设置页，手机也可操作；内核未运行时显示异常，提示关闭后重新开启。
- 不修改真实路由器的配置、运行策略或网络规则。
